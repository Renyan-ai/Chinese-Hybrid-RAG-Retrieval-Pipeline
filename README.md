# 中文混合RAG检索管道（面向中文PDF文档）

> 一个面向中文PDF文档的检索型混合RAG框架，具备语义表格解析、稠密-稀疏混合检索、查询融合、行级重排序以及基于RAGAS的自动化评估能力。

## 概述

本项目实现了一个面向检索的RAG（检索增强生成）管道，专为复杂的**中文PDF文档**（如财务报告）设计。

与传统RAG系统侧重于答案生成不同，本项目**聚焦于提升检索质量**，通过结合稠密检索、稀疏检索、语义表格理解与重排序技术，实现更精准的上下文召回。

管道完整支持：结构化PDF解析、语义表格处理、混合检索、查询改写、交叉编码器重排序以及自动化评估。

## 检索管道

### 1. 文档解析

系统使用 **Docling** 对PDF文档进行结构化解析，保留文档层级结构、文本段落以及表格信息。

### 2. 文本分块

采用递归分块策略，配合重叠窗口切割文本内容，以保持语义连续性。

### 3. 语义表格解析

与直接嵌入原始Markdown表格不同，系统将每个表格转换为**语义化的自然语言描述**。

**示例：**

原始表格：

```text
| 年份 | 营收（亿元） |
|------|-------------|
| 2025 | 7518        |
```

转换后表示：

```text
表格：财务摘要

年份：2025年
营收：人民币 7518 亿元
```

这种方式显著提升了向量嵌入质量和BM25检索效果。

---

### 4. 混合检索

检索系统组合以下两种策略：

- **稠密检索**（BGE Embedding）
- **稀疏检索**（BM25）

并通过**倒数排名融合（RRF）** 算法进行结果融合。

---

### 5. 重排序

检索到的候选结果经过两级重排序：

- **BGE交叉编码器** 重排序
- **行级重排序**（针对表格内容）
  

行级策略使系统能够定位大表格中的**最相关行**，而非将整个表格作为一个整体块进行排序。

行级重排序是针对大表格检索的精细优化策略。传统方法将整个表格作为一个整体节点进行检索和排序，当表格包含数十行数据时，模型只能为整张表打一个总分，难以精准定位用户真正关心的那几行。本项目在Cross-Encoder重排序之后，额外增加行级精排环节：将召回表格逐行拆解为「列名：值」的自然语言描述，使用Cross-Encoder对每一行与用户查询逐一打分，取最高分作为该表格节点的最终得分并重新排序，同时将得分最高的Top-3行内容存入节点元数据供最终输出。这一策略使系统能够从上百行的大表格中精准命中与问题最相关的几行数据，有效解决了传统方法「召回了整张表，却说不清哪一行有用」的困境。
---

### 6. 评估

检索质量通过 **RAGAS** 框架自动化评估，支持以下指标：

- **上下文精确度（Context Precision）**

项目同时提供检索消融实验，用于对比：

- 纯稠密检索
- 纯BM25检索
- 混合检索
